Manual

What it is

A service that keeps the YouTube channel of UMSA (Universidad del Museo Social Argentino) on air without interruptions. It takes prepared video clips and streams them in a loop with ffmpeg. Programming changes by itself according to Argentina time, following a six-block schedule.

New clips can be produced with artificial intelligence: a language model writes the script, Piper turns it into speech (it runs on the server itself, with no per-use cost) and ffmpeg builds the video over an institutional slide.

How to watch

The live channel player is at the top. Next to it you can see whether the service is streaming and which block matches the current time. If the player says there is no stream, the channel has not been set for this page yet (YOUTUBE_CHANNEL_ID variable) or streaming is stopped.

Below the player you can read English subtitles of what is on air. The stream itself is narrated in Spanish; the subtitles are translated from the script of each clip and computed on the server, so they may run a few seconds ahead of or behind the YouTube video. Videos uploaded without going through the AI pipeline have no subtitles.

During the day, each of the five schools has its own time slot with all its undergraduate and graduate programs. From 22 to 7, all of the university's programs rotate. Each block streams the clips whose name starts with its prefix. Prime Time has no content of its own yet: meanwhile, like any empty block, it streams the rotation of all programs.

How it works

The how-it-works graph reads from left to right:

  • Sources: the operator (from Swagger or with the .ps1 scripts), the language model (Anthropic, with OpenAI as fallback), Piper for the voice, the institutional slides and the clock in Argentina time.
  • Processes: POST /ai/clip chains script, voice and video. The scheduler checks every minute which block applies and rewrites the playlist. The streamer is ffmpeg streaming without re-encoding, and the watchdog restarts it if it crashes by itself.
  • Stored data: voices in media/audio, clips in media/videos and the list of what is on air in playlist.txt.
  • What it publishes: the YouTube Live signal, the status API and this page.

What content there is

The information graph links each schedule block with the programs it streams, school by school, with their level (undergraduate or graduate) and format as listed on the official UMSA website. Arrows to the rotation mark the blocks that stream all programs.

How to add content

  1. With AI: python scripts/cargar_carreras.py generates the clips for programs that have no video yet, from each program's official page. For a single clip: POST /api/v1/ai/clip with a topic, a nombre_archivo starting with the school prefix (for example hum_grado_psicologia) and, optionally, a slide from media/placas.
  2. Your own video: copy it to media/videos with the block prefix, already normalized to 1080p30 H.264/AAC. The scheduler picks it up at the next block change.

Technical documentation for each endpoint is at /docs.

Protection

This page, the status and the playlist are public. Starting or stopping the stream, changing the playlist and generating AI content require the X-Admin-Token header. In production the app does not start without that token, and without a language or voice model it returns an error instead of airing a simulated script or a silent clip.

Known limitations

  • Changing blocks restarts ffmpeg: the signal drops for a couple of seconds.
  • If a block has no clips and no fallback, streaming stops and does not come back by itself on the next block: it has to be started by hand.
  • Production mode is detected only inside Railway; on other hosting set APP_ENV=production.
  • There are no automatic subtitles or live-data slides yet.
